# AGENTS.md — aert/dotfiles

Three distinct areas:
- **`my_scripts/`** — shared executable scripts, intended to be on `$PATH`
- **`user-config/`** — per-user dotfiles symlinked to `~/`
- **`system-config/`** — system-level configs intended for `/etc/`

Multi-OS (Linux primary, Fedora/Debian), multi-DE (Gnome, KDE), multi-editor.

---

## Quick Start

```bash
./install              # Apply all dotfiles (symlinks managed by dotbot)
./install -n           # Dry-run — show what would change
sudo ./install system  # Apply system-level /etc/ configs
```

## Dotbot (Dotfile Management)

Dotbot manages symlinks via per-OS config files. Key details:

- **Entrypoint**: `./install` (detects OS, composes config stack)
- **Dry-run**: `./install -n` to preview changes
- **Configs**: `install.conf.shared.yaml` (all machines) + OS-specific overlay (linux/fedora/darwin)
- **Behavior**: `create: true` auto-creates parent dirs, `relink: true` replaces stale symlinks
- **CI safety**: existing plain files at destination are NOT overwritten (Dotbot's default)
- **System configs**: `install.conf.system.yaml` for `/etc/` files — apply with `sudo ./install system`
- **Copying back**: if you change a config in `~/` and want to save it to the repo, copy manually: `cp ~/.zshrc user-config/.zshrc`

### OS Detection

| Machine | Configs loaded | Trigger |
|---------|---------------|---------|
| Debian/Ubuntu | `shared` + `linux` | `uname -s` = Linux, no `/etc/fedora-release` |
| Fedora | `shared` + `linux` + `fedora` | `uname -s` = Linux, `/etc/fedora-release` exists |
| macOS | `shared` + `darwin` | `uname -s` = Darwin |

## Utility Script Conventions

- **Ruby** is the primary scripting language (7+ scripts): `#!/usr/bin/env ruby` with `# frozen_string_literal: true`
- **Shell scripts** mostly use `#!/bin/sh` (POSIX), a few use `#!/bin/bash` when bashisms needed
- **Python scripts** use `#!/usr/bin/env python` (usually Python 3)
- Many Ruby scripts use `bundler/inline` for gem dependencies (activesupport ~> 7.0)
- Simulation/dry-run mode is a common pattern: `,clean-filename` defaults to simulation, requires `--force`/`-f` to execute
- **Comma prefix** (`,md-to-html`, `,md-preview`, `,md-to-pdf`, `,clean-filename`, etc.) for all scripts — these sort to top in directory listings
- Naming: dash-separated names, no file extensions

### Markdown Pipeline

The `,md-to-html` script is the most complex tool: supports GitLab-flavored markdown, Mermaid diagrams (rendered as inline SVG), YAML frontmatter stripping, standalone HTML or fragment mode, custom output paths. Preview via `,md-preview` saves to `/tmp/md-previews/`.

## Git Config Conventions

- **Aliases**: `lg` (pretty log), `lf` (file list), `co`=commit, `ck`=checkout, `di`=`diff --color-words`, `dis`=staged diff, `st`=status, `br`=branches sorted by date, `rbi`=rebase -i, `pr`=pull -r, `abort`=`reset --hard HEAD`, `recommit`=`commit --amend`
- **Pager**: `delta --theme=zenburn`
- **Diff**: meld as both merge and diff tool
- `quotepath = off` (handles non-ASCII filenames)
- `autocrlf = input` (LF line endings)

## Setup Machine Flow

New machine setup:

1. **Install prerequisites**: `mise install` (installs dotbot via pipx)
2. **Apply dotfiles**: `./install` — symlinks all configs via Dotbot (idempotent, creates parent dirs, replaces old symlinks). VSCodium extensions, packages, and desktop settings are also applied via dotbot shell directives.
3. **System configs**: `sudo ./install system` — links `/etc/` files (fstab, apt, dnf, sysctl)
4. **Gnome extensions**: see instructions in `other.rst`

## Known Gotchas & Issues

(See `IMPROVEMENTS.md` for full audit)

- **Hardcoded paths**: `,tplink-status` has `HOST = "192.168.0.1"` hardcoded
- **POSIX compatibility**: some `#!/bin/sh` scripts use bash `[[ ]]` syntax (should be `[ ]`)
- **Linux-only scripts**: `net-speed` reads `/sys/class/net/` — breaks on macOS
- **Missing dependency manifests**: No Gemfile, requirements.txt, or package.json for script dependencies
- **Dotbot-managed symlinks**: per-OS config files control all symlinks. Existing plain files are left alone; use `./install -n` to preview. Dotbot's `create: true` auto-creates parent dirs (e.g. `~/.config/`).
- **Commented-out sections**: `.zshrc` has many commented-out pyenv/nvm/asdf sections and virtualenv configs — these are dead code
- **`.gitconfig` references `~/.git_template`**: this template directory doesn't exist in the repo
- **PATH scattered**: `.zshrc` has PATH modifications spread across multiple lines rather than consolidated
- **README.md is minimal**: says almost nothing — just Gnome Terminal font/color settings
- **Ghostty config has a `macos-titlebar-style` setting**: this config is shared cross-platform
